# Hosted Workspace Runtime confinement

[简体中文](2026-11-21-managed-hosted-confinement.zh-CN.md)

[#15081](https://github.com/QwenLM/qwen-code/issues/15081) · [#14667](https://github.com/QwenLM/qwen-code/issues/14667) · [Initial design](https://github.com/QwenLM/qwen-code/pull/15163)

## Scope

The Broker can opt its local, durable, Session-exclusive Hosted Workspace Runtimes into a private Linux root. This slice admits the bounded Tool v2 foreground Shell of the dedicated `hosted-workspace-confined-shell/1` profile for a built-in agent Session bound to the root of its registered Workspace. It gives the command the approved Workspace as `/workspace`, a deployment-staged read-only image, private temporary storage and closed networking. Native file tools, process services and executable extensions require separate admission work.

The selected worker remains trusted host control code and retains the existing authenticated loopback protocol. Every admitted command runs through the private-root launcher. The worker, launcher and payload are in the original Runtime's cgroup, so lifecycle cleanup can prove that the whole Runtime stopped even when the worker no longer answers.

## Selection and configuration

An explicit `qwen.managed-agent.runtime-broker.provider-options.private-rootfs` setting enables the profile. The setting names a canonical, deployment-owned private image with an executable `/bin/sh`. It requires a canonical `/usr/bin/bwrap`, the existing `qwen.managed-agent.runtime-broker.provider-options.cgroup-root` opt-in, durable local-process provisioning, Linux, an unprivileged service account and exclusive Session isolation. The setting also requires publication, executable extensions, child workspaces, child agents and web terminal to be disabled. The first release supports the built-in agent with no model-facing extension, hook, MCP, client file, skill or process service. Ineligible local placements return a typed denial. External and SSH placements keep their separate capability and do not advertise this guarantee. The setting is immutable for a Broker process and is qualified with Bubblewrap 0.8.0. The operator must stop admission and drain existing local Runtime leases before a rollout. The operator provides stable, non-overlapping roots without host sockets, device nodes, nested mounts or hardlink aliases to protected files. The image and executable are trusted deployment artifacts.

While configured, admission for a new local built-in Workspace Session persists `hosted-workspace-confined-shell/1` in its existing profile field under the Workspace creation lock. It refuses missing or unsupported prerequisites, non-root cwd and optional tool configuration. The profile is internal to the built-in admission decision. The control plane selects the reserved capability digest only for that saved profile and an eligible local Workspace. Existing ordinary Sessions retain their own profile. While the setting is enabled, an ordinary saved Session on a covered local placement can recover and clean up its original work. New warm, acquire, reserve and dispatch operations require the saved confined profile. A confined Session with disabled configuration cannot warm or acquire a replacement ordinary Runtime. Its saved scope and worker boot/attestation are distinct from ordinary, external, SSH, resident and extension profiles. Binding comparison excludes ordinary-profile rollout equivalence in both directions. The database schema already supports the profile name.

The local v3 registration stores a private-root recipe (canonical image path, device/inode identities for the image and fixed Bubblewrap executable, and protocol revision) alongside the original cgroup identity. A pre-launch registration writes the recipe from current configuration. Reads reconstruct an existing handle from its saved recipe and compare it to the Broker handle. Boot and exact attestation carry the same recipe. The server and worker compare the current recipe to the pinned one on launch, adoption and admission. The image content is an immutable deployment artifact for the lifetime of the binding. Path identity alone does not certify unchanged content. Cleanup always reconstructs the saved cgroup handle and remains possible after configuration changes. A confined request with an absent or non-v3 handle cannot take the legacy PID stop path. A deployment must drain affected existing leases before changing the profile or image. Placement requires verified Workspace storage identity. An enabled profile cannot launch with a non-cgroup handle. Runtime admission compares against the resolved scope for existing bindings as well as newly provisioned ones. Cleanup selects the saved scope and does not require current launch eligibility.

The deployment passes the pinned configuration through the trusted worker bootstrap. The worker verifies the capability, configuration and Workspace root together, and qualifies the private-root launcher with a bounded no-op under containment before successful attestation. The ready record locates the control endpoint. Qualification failures are returned only for a matching authenticated attestation, with an exact code that the Java transport preserves. Failed qualification leaves tool admission and context installation closed. Failure returns `managed_runtime_confinement_unavailable` and leaves the binding fenced. A later launch failure does not dispatch the same command through any ordinary executor.

## Admission and tool result

The Hosted Connector carries the saved confined profile during create, load and recovery, including when launch has been disabled. On an active attach the Harness only enables the v2 foreground Shell result lane. It verifies the exact Broker capability before warm and tool admission. The Harness and Java classify the profile separately from the general Shell profiles and include it in their lifecycle v2 negotiation. Cleanup attach does not warm or need to discover a current launch capability. Control Plane gating and the closed worker route plan protect against an older Harness, which cannot downgrade the selected Runtime. Cleanup and cancellation use the saved scope without widening admission. Model declarations expose only Shell and reject any other name before reserving, resolving extensible tools or invoking host-backed helpers. The Broker and selected worker independently enforce this allowlist before dispatch, including raw Tool v2 calls. The Session root must be ".". Shell input cannot select a directory or use background or Monitor. The Harness disables file backup binding, recovery and project instruction reads for the confined lane. Foreground-only Shell retains the saved approval mode (default or auto-edit), approval prompts and owner-only action responses. It omits Plan mode and dynamic approval selection. Unsupported operations receive `managed_runtime_confinement_denied` at admission. Requests to undeclared worker endpoints receive the existing route-not-found response.

The confined worker exposes only attestation, install, activation and Tool v2 execution, result, cancellation and acknowledgement routes. Activation with operation release closes the logical Session without sending a Provider request. Provider dispatch, Tool v3/v4, file/undo, MCP, hooks, background and publication, extension, monitor and terminal routes cannot run on the confined worker or use an alternate worker for its Session. The worker runs fixed `/bin/sh -c` inside Bubblewrap as PID 1 in a new PID namespace. Bubblewrap must wait for the namespace init to exit before reporting the connected status. Linux completes teardown of remaining namespace processes as part of that exit. The Worker keeps bounded v2 output and emits it only on a confirmed result. A normal nonzero code is a Shell result. A rejection proved before handing off to the launcher can be represented by the existing settled-v2 envelope with a typed not-started result. An interrupted, missing or unreadable outcome that cannot prove no execution enters the existing unknown journal state and cannot be replayed. Raw launcher diagnostics are omitted.

## Handback and retirement

A normal successful turn can release its mount on the live path. The Runtime Session enters RELEASING, the original authenticated worker closes tool and activation gates for that Session, and certifies that the Session has no pending starts, executing or unknown calls, or unconfirmed namespace teardown. The Broker also checks the exact registration and reads the descriptor-bound cgroup, refusing if the worker is not the sole direct member or there are subgroups. This snapshot can conservatively deny a release while another turn is executing. It complements the per-Session closure and per-command PID namespace evidence. The normal ownership transaction locks the binding and the Runtime Session and compares the exact versioned handle, binding generation and `RELEASING` owner before clearing that member. An in-flight or unknown execution, missing or changed identity, any extra member, or no worker response retains ownership. Recovery-blocked mount-only handback is refused with `workspace_writer_unproven`, leaving the Runtime Session active or RELEASING until the original proof arrives.

The terminal path refreshes the exact drain claim, stops the original descriptor-bound cgroup, verifies `populated 0` and absence of the recorded worker, and persists retirement before issuing its existing receipt. The transaction matches binding, generation, request and handle before releasing ownership. An execution still UNKNOWN can block ordinary drain, and an already LOST binding with a populated cgroup requires the existing fenced stop/recovery procedure. Its exact JOURNAL_LOST plus WRITERS_STOPPED evidence is the existing alternative for the same original cgroup. Unconfirmed stopping keeps ownership and returns `workspace_close_stop_unconfirmed` or the current typed identity/recovery failure. A same-name replacement group can neither prove the old group empty nor be killed using the old claim.

## Acceptance

- With the setting unset, existing Hosted selection and result handling remain compatible. Ineligible placement or invalid prerequisites cannot dispatch with a confined binding or fall back to an ordinary worker.
- With a real Linux private image and cgroup v2, an eligible selected Hosted Runtime runs a foreground Shell command. It can read and write its own Workspace. Host and other Workspace sentinels, the host environment and network are absent. A detached descendant must prove it started and closed inherited standard streams, and it must be gone when its command reports a confirmed result. A separate setup failure must keep admission closed. A normal nonzero Shell exit is distinguishable from refused admission and execution uncertainty.
- Harness, Broker and worker deny unsupported tools, cwd, background and alternate execution routes. Reused and stale identities do not gain admission across capability, generation or configuration changes.
- On worker death with a remaining cgroup member, early handback cannot clear the holder. Broker terminal drain proves stop independently of the worker once the terminal prerequisites are satisfied. Test that an UNKNOWN row retains ownership, and that a missing or replaced cgroup never produces a receipt for the original handle.
